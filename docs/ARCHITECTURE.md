# Architecture

Snapshot of what the code shows as of 2026-10-03. The project is at the importer stage: a window, a free-fly
camera, an OpenGL renderer, and importers that load Sonic (SADX GameCube) and Shadow (Shadow the Hedgehog GameCube)
models with textures straight from the disc images, and play one looping idle motion on each (Sonic's Ninja motion,
Shadow's `.MTP` motions with skinning), and levels drawn from the disc with frustum culling: an SADX land table (Emerald Coast) and Shadow stages (RenderWare worlds, stg0000 / stg0100). No gameplay or lighting is implemented yet.

## Build
- CMake (>= 3.28), C++23, `CMAKE_EXPORT_COMPILE_COMMANDS ON`. Single target `SonicSunset`.
- Existing `build/` is configured with Ninja, `CMAKE_BUILD_TYPE=Debug`.
- Linux only as written: links the vendored static `third-party/GLFW/lib/libglfw3.a` (loads X11 via dlopen), `pthread`, `m`, `GL`, `dl`.
- New `.cpp` files must be added to `add_executable` in `CMakeLists.txt` by hand.
- Include directories are `src` and every folder below it that holds headers (`src/Objects`, `src/Graphics`,
  `src/Graphics/Resources`, `src/Graphics/InstanceData`, `src/Importers`, `src/Importers/GameCube`,
  `src/Importers/Ninja`, `src/Importers/STH2005`, `src/Importers/Renderware`, `src/Loading`, `src/Keys`, `src/Misc`), so headers are included by bare name
  (`"Camera.h"`, not `"Objects/Camera.h"`). A new folder needs adding to `target_include_directories`.
- The executable runs with cwd `build/` (`.vscode/launch.json`, lldb). The `CopyShaders` target copies the repo's
  `Shaders/` to `build/Assets/Shaders` on every build. The placeholder SADX model folder (`Assets/External/Models/<n>.sa1mdl`, `Assets/External/Textures/`, `Constants.h`) is
  read relative to `build/` and is copied from the source tree's `External/` by `CopyExternal`.
- The disc images are read from `Disks/Shadow2005.iso` and `Disks/SADX.iso` (`Constants.h`), i.e. `build/Disks/` (the executable runs with cwd `build/`).
- `.gitignore` excludes `build/`, every folder starting with a dot, and `sadreamcasttools/`.
- The CMake setting `EDITOR` (one `set(EDITOR ... CACHE BOOL ... FORCE)` line in CMakeLists.txt; edit it to switch, a `-D` flag is ignored) defines the `EDITOR` macro and adds the editor sources (all editor code lives in `src/EngineEditor/`: `Editor.h/.cpp`, `EditorCamera.h/.cpp`, `Gizmo.h/.cpp`, `Debug/` and `Panels/`): `Editor`, `DebugUI`, `CollisionView`, `Text`, the `Gizmo`, the `EntityListPanel`, `InspectorPanel`, `PrefabPanel` (with `AssetPanel` and the two thumbnail makers) and the ImGui files. Everything of the editor is owned by the one global `editor` (`struct Editor`, `Editor.h`): `active` (editor mode; starts on in the EDITOR build; the toolbar's Play button / the Debug window's Stop button or Esc switch it, `Editor::setPlaying`), `debugMenuOpen` (while playing: Tab opens the Debug window with a free cursor), `cursorFree` (true whenever the editor is active except during a mouse button hold), the debug UI, collision view, labels, the transform gizmo, the entity list, inspector and prefab panels, the key handling (`Editor::processInputs`: fly keys, button holds, Tab (debug menu, only while playing), Esc (stop, only while playing), C, V, arrows, 1 / 2 / 3 = gizmo mode) and `camera`, an `EditorCamera` (a `Camera` plus controls) of its own. Under `#ifdef EDITOR` are: `Editor`, its calls in `Renderer::runAll`, `main.cpp` and `Utils.h` (mouse, resize), the placement markers in `Level.cpp` (`editor.collisionView.markers`), `DebugSetup::addShadowPlacementMarkers` and the GL debug output (`Utils.h`, `Debug.h`). Everything else asks `editorActive()` (`Editor.h`; always false without EDITOR), e.g. Lua `sf.debugMode()`, so the player is controlled only outside the editor and, without EDITOR, always. The toolbar has a File menu: Save writes the current level's edits (moved own entities, entities added with the prefab panel; each with its position, rotation, scale, behaviours, bound area, model and texture) into the level file's `"edits"` (`Loading::saveLevelEdits`, docs/ENGINE_USAGE.md), Save as writes them to another file name, Save Source Game Level (`Editor::saveSourceLevel` → `Loading::saveSourceLevel`, written at once, then the level is loaded again) makes the level as it is now the level's source: the file's `"source"` object plus `Levels/<level>/SourceGamePrefabs/` for the prefab-wide edits (the level's source set in `Prefab::inLevels`, a layer between Changed and the level's edits; docs/ENGINE_USAGE.md), applied by `loadLevel` before `markSourceEntities` (added entities of the source become the level's own), and Restore Source Game Level puts the level back as that source has it, the game's data when there is none (`Level::restoreSource`, not written until Save). 2026-10-08, nothing built or run. The inspector's "Return to Source Game state" does the same for one of the level's own entities (`Level::sourcePositions`, `sourceIndexOf`, `revertSourceEntity`). `Loading::loadLevel` marks the entities the game's data made (`Level::markSourceEntities`), then applies the file's edits. Escape stops the play. File > New level asks for the engine, shader and disc paths, writes the level file to `Assets/Levels` and `Levels/` (`Loading::createLevelFile`; a name that exists is refused) and loads it (`Editor::newLevel`; not run). File > Load level lists the files of `Assets/Levels` and replaces the loaded level with the chosen one (`Editor::loadLevel` = `Scripting::resetGame(name)`: game.lua's `resetGame(unloaded, name)` loads it; a level without an entry in game.lua gets placeholder starts); unsaved edits of the old level are lost.
- **The transform gizmo** (`Graphics::Gizmo`, `EngineEditor/Gizmo.h/.cpp`, `Editor::gizmo`; written 2026-10-08, nothing built or run): move / rotate / scale handles on `entityList.selected`, active while the editor is. Keys `1` / `2` / `3` pick the mode (`Editor::processInputs`; W is a fly key so W E R is not used; ignored during a drag, a camera hold or a text field). Move: three arrows along the world axes (`setPosition` by the cursor's closest point on the axis line, relative to the grab). Rotate: three rings about the world axes (`setRotation(rotate(delta, axis) * startRotation)`, delta = angle the cursor sweeps around the entity in the ring's plane, wrapped to (-pi, pi]). Scale: three boxes at the ends of the entity's own axes (the columns of `rotation`, the axes `Entity::scale` acts along; `setScale`, factor 1 + (t - t0) / handle length, clamped to 0.01 minimum). Handles are 110 px long at the entity's depth (world size through the camera's fov), picked within 8 px by a ray from the cursor (`glfwGetCursorPos` through the inverse of projection * view) against the handle shapes in the world: arrow = segment, ring = 64 segment polyline, box = slab test; the closest wins and is drawn yellow (x red, y green, z blue). A handle whose start cannot be read (an arrow along the view, a ring edge on) is not grabbed. Drawn with ImGui's background draw list inside `DebugUI::draw` after the labels (no depth test, constant screen size, thick lines are free; chosen over a GL line pass like `CollisionView`, whose lines are 1 px in a core profile and which would need its own buffers and shader for heads and boxes). `Gizmo::update` runs in `Editor::processInputs` before `EditorCamera::updateDrag`: a left press on a handle starts a drag and `wantsMouse()` (true while dragging) is or-ed into the UI's, so the camera does not pan; a press that began on the camera or the UI never grabs a handle moved over; the selection is never changed by it. On release the spatial index is marked dirty (`setScale` already does through `refreshBounds`, every frame of a scale drag). Limits: no undo; rotation and scale are kept at Play / Stop (`Editor::KeptEntity`) and saved (`"edits"` `transforms`, `added[].rotation/scale`, docs/ENGINE_USAGE.md; `Level::sourceRotations/sourceScales` are the source to diff against and revert to; written 2026-10-08, not run); the inspector has no rotation or scale fields. **Click to select** (2026-10-08, not run): a left press on the scene that the UI, a gizmo handle and a camera hold did not take, released (cancelled by a camera hold; the left button no longer pans, so there is no movement threshold, changed 2026-10-08, not run), selects the entity under the press (`Graphics::pickEntity`, Gizmo.cpp: changed 2026-10-08, not run: changed 2026-10-09, not run: an entity with a model is hit where the ray crosses one of the model's triangles (`Entity::rayHitsModel`: the ray taken into model space by the inverse of the draw transform, ONE's `RenderWareYawDegrees` included; Moller-Trumbore on the CPU `BasicMesh` vertices, both sides, per mesh node/frame world matrix; SA models use `SAInstance::nodePose` when built, i.e. as last drawn, ONE models the rest pose (skinned atomics as if on their frame, like the bounds); the rest pose box `BoundingSphere::boxLow/boxHigh/boxValid`, set by `SAMesh/RenderWareMesh::computeBounds`, only rejects early and is skipped for a posed SA model; external models (`pOverrideModel`) are tested by their pool meshes; the entity's collision shapes are not part of it); entities with no readable triangles (no model, custom vertex layout) are the bounds sphere moved by position and rotation, at least 12 px on screen so cameras and model-less entities can be clicked; the nearest hit wins. Replaces the earlier smallest-sphere rule); a miss keeps the selection. **BoundArea tab view**: while the Inspector's BoundArea tab is shown (`CollisionView::boundAreaTabActive`, set by the inspector like `entityTabActive`, so one frame late) the entities' shapes are drawn although the C view is off (level lines stay off), the selected entity's in white. **Mesh / Texture tabs**: the slot line shows the model / texture in use (`Entity::discMesh` / `discTexture`, `External: name` when an external one is set, `(default)` after it when the choice is Default); the prefab box on Default says each entity keeps its own.
- **The editor camera** (`Editor::camera`, `struct EditorCamera : Camera`, `EngineEditor/EditorCamera.h`) is not an entity and not in `Globals::Game::cameras`: no entity list entry, no Lua access. While `editor.active` it is the only thing `Renderer::runAll(&editor.camera)` draws to the screen (render-target cameras still render; the gameplay screen cameras are skipped) and it takes the mouse (`mouseCallback`) and the fly keys. The gameplay cameras (`mainCamera`) take neither, keep following `cameraTarget` (`updateFollowCamera`, every frame) and stay what `GameplaySystem::tick` culls by. Stop (back into the editor) copies the gameplay main camera's position and look direction (`matchGameplayCamera`; `main.cpp` also does it once after `game.lua`), not its planes or fov. The collision view is drawn for the editor camera only (in `runAll`). The inspector's "Add camera" puts the new camera at the editor camera. Written 2026-10-08; nothing built or run yet. Controls (written 2026-10-08, nothing built or run): the cursor stays visible while the editor is active; W A S D / Space / Ctrl fly (Shift = full speed, `speed` x `speedUp` without `zoomScale`, changed 2026-10-09, not run, same for the wheel; skipped while an ImGui text field has the keyboard, `DebugUI::wantsKeyboard`); holding the right button turns the camera (`processMouse`), holding the middle one pans it along the camera's right/up by `panPerSpeed` x `speed` per pixel (0.005 x 100 = 0.5); a hold starts only where the UI does not cover (`wantsMouse`) and hides and captures the cursor; the wheel (`scrollCallback` → `Editor::onScroll`, not when the UI has the mouse) moves along the look direction by `zoomPerSpeed` x `speed` (0.2 x 100 = 20, x`speedUp` with Shift), and no longer changes any speed. Fly, pan and zoom steps are scaled by `zoomScale` = distance from the camera to the surface of the selected entity's bounds sphere (changed 2026-10-09 after the user saw the camera get slower with every wheel notch; not run), and with no selection the distance to the model the camera looks at (not run: nearest triangle on the view ray over all entities, `Entity::rayHitsModel`, measured ten times a second in `Editor::processInputs`; nothing within `farPlane` = the maximum; the earlier `SpatialIndex::nearestDistance` sphere distance is no longer used by the editor) / `referenceDistance` (slider, default 10, saved), clamped 0.001..10 (max lowered from 100 on 2026-10-09, user: too boosted; not run) and eased towards that target in log space (`EditorCamera::updateSpeedScale`, rate 8/s, a guess). Replaces the earlier wheel-driven scale (x1.15 per notch), which only drifted and was never reset. Written 2026-10-08, not built or run. Correction 2026-10-09 (user: WASD broken, zoom too slow close to entities): the sphere of a big level entity makes the distance 0 inside it, so the camera sat at minimum speed (hypothesis from the code, the cause was not measured); replaced by the view ray distance above. Play captures the cursor, Stop and the open debug menu free it. In editor mode `GameplaySystem::tick` runs only `collisionSystem.update()` (each active entity's `stagingPosition` set to its position first, so it only pushes out of overlaps; the interaction (onTouch) calls at the end of the three collision paths are skipped in editor mode): no behaviours, physics, dash trail or effect balls; `Entity::update` (motions) and `gameEvents.drain` still run every frame. Stop resets the game: `Scripting::resetGame` calls the script's global `resetGame(false)` (`game.lua`: `sf.unloadLevel`), removes the level at once (`processPendingUnloads`), calls `resetGame(true)` (`enter(current)`: level loaded again from its JSON, players back at its start, velocity 0), then the editor clears the selection and rebuilds the spatial index. So entities added or moved in the editor and the objects' state vanish, The players' `sf.state` tables are wiped and given their starting contents again (`resetPlayers` in `main.lua`, via `initSonicState` / `initShadowState`); other Lua locals (replay, animation module state) are not reset. `Level::destroy` clears all collision-view markers (one level at a time). Written 2026-10-08, not run. The old Esc cursor toggle and the left-click recapture are removed. Stop reloads the level from its file but then puts back the positions and added entities the editor had at Play (`Editor::keptLevels`: one `KeptLevel` per level alive at Play, by name, holding `own` / `added` / `prefabs` / `cameras`; one `KeptEntity` per entity), saved or not. Every level alive at Play is kept, so a level play left (unloaded by a transition) or a neighbour is loaded again by name at Stop and restored the same way (`giveKeptLevel`); a level of that name still alive is dropped first. Changed 2026-10-13, not run.
- **Editor shortcuts** (`Editor::processInputs`, written 2026-10-08, not built or run; only while the editor is active, no ImGui text field has the keyboard, and the camera is not in a button hold): with Ctrl (either one) held, Ctrl+Z undoes, Ctrl+Y redoes, Ctrl+C copies the selected entity, Ctrl+V pastes it and Ctrl+S saves every loaded level, each into its own level file (`Editor::saveAllLevels`, as File > Save; Save as... writes only the current level, `Editor::saveLevel`; 2026-10-14, not run). C and V still toggle the collision view without Ctrl; with Ctrl and Z/Y/C/V/S held the fly keys do nothing. Undo/redo (`Editor::undoStack` / `redoStack`, 200 steps, a new step empties the redo ones; both dropped by `loadLevel`, `restoreSourceValues` and `setPlaying`): a step is a transform change of the selected entity (`trackTransform`: a gizmo drag or an ImGui widget being held is one step, a change with nothing held, e.g. the collision system pushing out of an overlap, is not) or an entity made by Add camera / paste / the prefab panel's spawn (undo removes it from the level and the pool, keeping its state; redo makes it again with a new PoolId and renames the old one in both stacks). Nothing else is undoable (behaviours, shapes, model, texture, externals, prefab edits). A camera entity and its camera are at one position: `Entity::setPosition` / `moveTo` call `moveCameraModule`, and `updateFollowCamera` (main.cpp) moves the main camera through its entity, so the gizmo, the inspector Position, undo and the saved level agree (2026-10-09, not built or run; `Camera::set` / `move` move the entity too, via `Camera::moveEntity`, and each direction stops when the other is already at the position). Copy (`snapshotOf`): a prefab entity as prefab + `KeptEntity` (players refused), or a camera entity as the camera's own settings (not its render target); paste (`spawnFrom`) puts it where the cursor's ray crosses the horizontal plane through the copied entity (`Graphics::pickPlanePoint`; no ray against level collision exists), or at its old place when the cursor is on the UI; a prefab copy is added to the level's `entityIds`, so it is saved like a prefab-panel entity (cameras are saved: level file `"cameras"`, ENGINE_USAGE.md; a pasted or added camera is in `Level::entityIds`, kept over Play/Stop in `KeptLevel::cameras`).
- Lua 5.4.7 is vendored in `third-party/lua` (MIT; the interpreter and compiler programs left out) and built by `CMakeLists.txt` as the static library `lua`, compiled as C++ so a Lua error is a C++ exception, `LUA_USE_POSIX` only (no dlopen). The repo's `Scripts/` folder is copied to `build/Assets/Scripts` on every build by the `CopyScripts` target, like the shaders.
- `ENGINE_DEBUG` gates the validity checks in `Pool`/`PoolMap` (including the missing-name error in
  `PoolMap::getIdByName`); `CMakeLists.txt` defines it for Debug builds.
- `PoolMap::add` accepts a duplicate name (`nameToId` keeps the first; entities rely on it); `PoolMap::addUnique` throws instead, with nothing added (the external texture scan uses it).

## Runtime flow
1. `createWindow` (`Utils.h`): GLFW, OpenGL 4.5 core, debug context, cursor disabled,
   framebuffer-size and cursor-pos callbacks.
2. `Graphics::renderer.init()`: loads GLAD, enables sRGB framebuffer, depth test,
   back-face culling (CCW front), loads the `Default` shader and builds the debug floor mesh.
3. `addCamera("MainCamera", pos)` makes an entity with a `Camera` module (`Entity::cameraId`, a `Pool<Camera>` in `Globals::Game::cameras`); the first camera made is `Globals::Game::mainCamera`, the player camera (`getMainCamera()` in `API.h`).
4. `main.cpp` adds the `SA`, `STH2005` and `GLTF` shaders, opens both discs into `Globals::Discs` (they stay open), then runs `Scripts/game.lua`, which picks the level (its `LEVEL` variable, a table of the camera start and player start positions per level) and calls `sf.loadLevel(name)` (`Loading::loadLevel` reads `Assets/Levels/<name>/<name>.json` and runs, by its `engine`, `setSAGPUInstance` / `setSACollision` / `setSAEntities` (`"sadx"`) or `setONEGPUInstance` / `setONECollision` / `setONEEntities` (`"sth2005"`); levels: `EmeraldCoast`, `Stg0100`, `Stg0000`), `sf.setCamera(x, y, z)` and, for each player, `sf.spawnPlayer("sonic" | "shadow", x, y, z)` followed by `attachPlayer(entity)`. The recipes behind those names are the JSON files in `Levels/` (copied to `Assets/Levels` by `CopyLevels`; the generated entity tables they name are registered in `LevelLoader.cpp`); scripts never hold resource keys. A player is an `Entity` (position only) and its instance from the keys of `Loading::sonicKeys()` / `shadowKeys()` (`External/Players/*.json`, read once in `main` after the remaps): `setSAGPUInstance(saShader, mesh,
   textures)` then `playSAMotion(idle)`, `setONEGPUInstance(oneShader, mesh, textures)` then `playONEMotion` of each of `idle` (the body's and the two hands'), then physics of weight 1 (the body shape is the prefab's Changed file's, applied after the entity is made). Nothing is imported before that: the
   instance finds or loads what its keys name (see Entity, TextureSet, STH2005::ONE below) and holds one user of it. Switching level while running: `game.lua` gives the first player the behaviour `LevelSwitch` (L unloads the level with `sf.unloadLevel(level)` and loads the next of its `ORDER` one tick later, `sf.levelExists` says when the old one is gone; the players are moved to the new level's starts and `recordPlayerStarts()` of `main.lua` updates what R returns them to). Ground snap by level game (experimental, 2026-10-11, not run): each `LEVELS` entry of `game.lua` has `game` ("sadx"|"sth2005"); on every level load a player whose own game (`SASonic` sadx, `Shadow` sth2005) differs gets the behaviour `GroundSnap` (given once, on demand) that applies that game's snap mode (`sf.setGroundSnapMode`: sadx = stepped probe, no rising rule; sth2005 = ray probe, radius 0, 80 degrees, blockedByWall) after the character's own behaviour every tick. Hypothesis: a character in the other game's level uses the level's snap. A level of the character's own game writes the character's native mode once (the foreign one stays in the body otherwise). A level without `game` changes nothing. The ray probe skips a rising body unless `snapWhileRising` (as the stepped snap does; Shadow's script sets it true, so his probe is unchanged), because otherwise a jump of SADX Sonic in an sth2005 level was snapped back to the floor (not run). `sf.unloadLevel` only queues the level: `Scripting::processPendingUnloads` removes it (with its collision and entities, `Level::destroy`) at the start of the next gameplay tick, because the systems have already read the active entities during a tick. Not run.
5. Loop: compute `Globals::App::deltaTime`, poll events, `processInputs()`, `Entity::update(deltaTime)` for every live
   entity (advances SA and ONE motions), `renderer.runAll(editor.active ? &editor.camera : nullptr)` (every enabled camera: those with a render target first, then those that render to the screen; per camera `run`): clear,
   bind the camera UBO at binding 0, call `Level::draw(camera)` for every live level (the debug floor is commented out), then `Entity::draw` for every live entity. Then `editor.draw()` (`DebugUI::draw` with the editor, if active; ImGui, a separate pass) and `glfwSwapBuffers` in `main.cpp`.
6. `renderer.destroy()`, `destroyWindow()`.

## Core pieces
- **Globals** (`Globals.h`): `inline` variables in `Globals::App` (window, size, frame timing), `Globals::Game`
  (cameras, `entities`, `levels`), `Globals::Discs` (the two opened `GCDisc`s), `Globals::Mouse`. `Graphics::renderer` and the `basicMeshes`/`textures`/
  `textureSets`/`textureBindings`/`shaders`/`saMeshes`/`oneArchives` pools and instance pools live in `GPU_Globals.h`.
- **Pool<T> / PoolMap<T>**: deque-backed slot storage with generational `PoolId
  {id, generation}`, free-slot reuse, `alive` flags. `PoolMap` adds name lookup (`nameToId`; adding a duplicate name
  keeps the first id; `remove` drops a name only if it points to the removed slot). `remove` calls the element's `destroy` if it has one. The storage is a `std::deque`, so `add` never moves existing elements: a reference from the pool (`getEntity`) stays valid until that slot is removed and reused. Across anything that removes (a behaviour or callback that destroys entities), keep the `PoolId` and look it up again. `UninitializedPoolId` in `Constants.h`.
- **Camera**: yaw/pitch mouse look (pitch clamped to +-89 degrees), 45 degree perspective,
  `nearPlane` (1, for depth precision) / `farPlane` (50000 set in `Camera.h`; a slider in the inspector's Cameras tab, up to 500000, changes it and the projection). `farPlane` is also the one render distance: levels stream by it and entities are drawn and active within it. `speed` (50 in `Camera.h`) is the free-fly speed in
  units/s and `speedUp` (3) multiplies it while Left Shift is held (`Editor::processInputs`, on the editor camera; the fields exist on every camera but only the editor's are used). When the window regains focus the next
  cursor position becomes the mouse baseline (`focusCallback`), so the camera doesn't jump. `frustumPlanes()` returns the six view
  frustum planes (inside = `dot(normal, p) + d >= 0`) and `sphereInFrustum` tests a sphere against them. `view` and `projection` are uploaded to a UBO (`std140`,
  `CameraData { mat4 view; mat4 projection; }` at binding 0) on every change.
- **Cameras and render targets** (`Objects/Camera.*`, `Graphics/RenderTarget.*`, `Renderer::runAll`; made 2026-10-08 with the editor, not run): a camera is a module of an entity like collision and physics: `Entity::cameraId` into `Globals::Game::cameras` (`Pool<Camera>`, `addCamera` makes both; `Entity::destroy` removes the camera), the `Camera` knows its `entityId`. Several can exist; `Globals::Game::mainCamera` is the one the mouse look, the follow camera, the debug flying, `sf.setCamera` / `sf.cameraForward` / `sf.followCamera`, the entity labels and the gameplay's activation distance use. A camera has `fov`, `enabled` and `renderTargetId`: `UninitializedPoolId` = the screen, otherwise a `Graphics::RenderTarget` in `Globals::Game::renderTargets` (`addRenderTarget(w, h)`; framebuffer, `SRGB8_ALPHA8` colour texture, 24 bit depth renderbuffer, `displayTexture` = the same texture viewed as plain RGBA8 for ImGui). `Camera::setRenderTarget(id)` / `setRenderToScreen()` choose it and rebuild the projection from the aspect of `viewportSize()` (the target's size, or the window's; a removed target falls back to the screen); the window-resize callback only refreshes screen cameras. `Renderer::runAll` draws every enabled camera: render-target cameras first, each in its own framebuffer and viewport, then the screen cameras in pool order (a later one draws over an earlier one: no viewport rectangles yet). Limits: the camera keeps its own position, it is not tied to its entity's transform; culling, level streaming and the simulation use the main camera only; no Lua bindings for cameras or targets beyond the three old calls.
- **BasicMesh** (vertex layout added 2026-10-08, not run): an interleaved vertex buffer whose format is data, a `VertexLayout` (`VertexLayout.h/.cpp`): members (name, type Float/Vec2/Vec3/Vec4/U8Vec4, shader attribute location, byte offset), tightly packed, plus the `stride`. `addMember` appends (throws on a taken name or location), `memberIdFromName`, `setupVertexArray(vao)` describes every member as an attribute on binding 0 (U8Vec4 as an integer attribute, the rest as floats). `VertexLayout::standard()` is the layout of the struct `Vertex` and what the SADX and Shadow importers use (locations 0 position `vec3`, 1 normal `vec3`, 2 uv `vec2`, 3 color `vec4`, 4 bone indices `u8vec4` (integer attribute), 5 bone weights `vec4`; both zero unless skinned); it checks its offsets against `Vertex` once and throws on a mismatch. `BasicMesh::verticies` is a `VertexArray`: the vertices as bytes in the mesh's layout (`pLayout`, standard by default, `setLayout` only while empty) that `create()` uploads as they are. With the standard layout it reads like a `std::vector<Vertex>` (`push_back`, `operator[]`, range-for, `size`, `resize`, `operator=` from a vector or a braced list), so the importers are unchanged; for any other layout those throw and a vertex is read and written by member (`setMember<T>(memberId, vertex, value)` / `getMember<T>`, type-checked against the member). Optional `uint32_t` index buffer, drawn as `GL_TRIANGLES` with whatever program is bound. Manual `destroy()`. A custom layout must outlive the meshes that point to it: external models' layouts are owned by `Graphics::vertexLayouts` (see External assets).

- **Collision behaviours** (`Keys/BAKeys.h`, `Objects/BABehavior.h`, `Objects/BABehaviors.*`): our own convention for what a collision is and does, not either game's. A *tag* is a category (`BATagKey` names it; `Globals::Game::baTags` is a `PoolMap<BATag>`, only the name and so the `PoolId` matter). A *behaviour* (`BABehaviorKey`; `Globals::Game::behaviors`, a `PoolMap<BABehavior>`) is a bag: `tags` (what it is), `availableCollisions` (a set of tag ids it is stopped by) and `availableInteractions` (tag id to a list of `BAInteraction`s, each a function `(parentEntity_, contactEntity_)`; a tag may have several, a function listed twice for an overlap is called once). For an overlap each side looks the other's tags up in its own two maps; with no match on either side it is skipped, so nothing branches on what the other is; a collision rule is only "there is one" (push out). A script finds a tag or behaviour by name (`BABehaviors::findTag` / `find`) and keeps the `PoolId`. `Globals::Game::baBehaviors` (`BABehaviors`, `init()` before anything is loaded) describes and fills both pools with the built-ins (tags `Solid`, `Pickup`, `Hazard`, `Death` and `Body`; behaviours `Solid`, `Pickup`, `Hazard`, `Death`, each with its one tag and no rules, `Body` with the `Body` tag that collides with the `Solid` tag, and `None`, `Passable` and `Object` with no tags) and, from the four remaps of `External/Collision/Remaps.json` (`ShadowLevel`, `SADXLevel`, `SADXShape`, `ShadowShape`: a `fallback` behaviour name and `values`, raw value as a hex or decimal string to behaviour name, plus a `note` with the evidence, ignored; read once by `BABehaviors::loadRemaps` in `main` after `init`, names turned into `PoolId`s in `BARemap` members `remapShadowLevel` etc.; a missing or wrong file, an unknown behaviour name or a raw value listed twice throws at startup), gives a collision its behaviours when `ResourceLoader` loads it (`BABehaviors::resolve`): `Physics::Collision::behaviorByValue` / `fallbackBehavior` per raw triangle value (`behaviorOf`) and `CollisionShape::behavior` per shape. `Collision::entityId` is the owning entity (`Entity::selfId`; none for a level's), the parent an interaction gets. The collision system compares `PoolId`s and tags only: a triangle is solid for a shape if the shape's behaviour `collidesWith` the triangle's; the interactions of both sides are called once per gameplay tick after the move, parent = the entity that owns the side's collision (`UninitializedPoolId` for a level), contact = the other. ## Importers
All importers take bytes already in memory (or a path for `.sa1mdl`), throw `std::runtime_error` on anything outside
what they support, and carry the evidence for each layout in a comment (decoded from a file, external source, or
hypothesis). None of them contains a model, texture, bone or archive-entry name: those come from the resource keys in `ResourceKeys.h`.
- **`GCDisc`**: opens `.iso`, reads the file table, `readFile(path)` reads one file on request.
- **`Rel`**: applies a `.rel`'s relocations against itself; pointers then equal file offsets. A `SaCompGC` compressed module is decompressed first.
- **`SaComp`**: `isSaComp` / `decompressSaComp`: the bit-stream LZ77 of the 20 compressed SADX `.rel` files (`_Stg*`, `_Adv*`, `_B_chaos6/7`,
  `_Minicart`, `_Shooting`). Algorithm external (X-Hax/SACompGC, derived from the game's own routine); output checked on four modules.
- **`SALandTable`**: `readSALandTable(bytes, offset)`: COL pieces (model offset, surface flags, bounding sphere) and the texlist names.
  Layout decoded from `_Stg01.rel` and checked on every land table in SA Tools' GC_SADX INIs. Animated parts are not read.
- **`SASet`**: `Ninja::readSAPlacements(bytes)` reads an SADX SET file (`Set0100S.bin`): u32 count + zeroed header up to 0x20, then 32 byte records `u16 type, s16 rotation[3] (BAMS), f32 position[3], f32 scale[3]` (the low 12 bits of the u16 are the type and the top 4 flags, 8 on 54 records of Set0100S, meaning unknown; the scale holds parameters, not a scale: values like 1.9, 60.0, 12.3 that differ per object kind. External, the decompile of `_Main.rel` and `_Stg01.rel` (`sadxDecomp/decompiled_stg01/`, built by `tools/decomp/sadx/runStg01.sh`): none of the Emerald Coast decor objects' code (palm trees, railings, coral ...) reads the task's scale fields (+0x2C, +0x30, +0x34); the shared objects that do use them as parameters, differently each: SPRING scales x by `scl.x` in some state, the dash panel divides by them, spikes scale by 1 + `scl.x/y`, and the collision-only objects (WALL, C CUBE, C SPHERE, C CYLINDER) take their shape size from them. So no uniform scale is applied; the size matches exactly on Set0100S (788 records). The type indexes the stage's object list.
- **`tools/sadxLiveTasks.py`** reads a Dolphin RAM dump of SADX (`sadxDecomp/mem1.raw`, Memory window > Dump MRAM, Emerald Coast act 1) and lists, for each SET record that is a live task, the exec / display / destroy functions as offsets into `_Stg01.rel` / `_Main.rel`, with the live angles and height next to the record's. Observed on the first dump (68 tasks): 48 of 62 matched records have the same position, angles and scale as their SET record (the game does not change them; parasols drop 1 unit to the ground), so the records' rotation is used as is, and the display function of each type is known exactly (`genSAEntityKeys.py` reads the models and rotation calls inside it).
- **`SAMdl`**: `importSAModel(name, bytes, rootOffset, bigEndian)`. One `SANode` per NJS_OBJECT (depth first),
  one `SASubmesh` per meshset, one vertex per poly corner with position and UV (255 = 1.0). A submesh keeps
  its material's `texture id & 0xFFFF` as `textureIndex`; the `TextureSet` is applied when an instance is created, not by the importer; `rootOffset` comes from an `SAModelKey`. Bit 23 (0x800000) of the material attributes is read as double sided (`SASubmesh::doubleSided`, drawn without back-face culling; hypothesis: Ninja's NJD_FLAG_DOUBLE_SIDE as remembered, unchecked on a file). Normals, vertex colors, material
  diffuse/specular and attributes are not read. Limits: Ninja Basic only, non-DX struct sizes. An NPoly meshset (type 2) is read like a strip (observed on Kiki's). An attach with no materials (the collision model "Pier Collision") is read untextured.
  Hypotheses (marked in `SAMdl.cpp` / `SAMesh.h`): rotation order, triangle winding, quad/strip corner order, texture id = index into the `TextureSet`'s file order.
- **`SAMotion`**: `readSAMotion(bytes, offset, nodeCount, bigEndian)` reads an NJS_MOTION (position, rotation, scale
  channels, linear only; anything else throws). Layout from SA Tools, confirmed on Sonic Idle.
- **`Gvm`**: `importGvm(setName, bytes)` decodes a GVM archive into the Texture pool (linear filter) and a new `TextureSet`
  (archive order); returns nothing. Limits: header flags `0xF` only, CMPR and RGB5A3 only, mip level 0 only, sizes in whole tiles.
- **`Txd`**: `importTxd(bytes)` decodes a RenderWare texture dictionary of GameCube textures into the Texture pool by
  name and returns the ids (in order and by name) for the caller to keep, with the file's own filter and addressing. Formats: C4 and C8 with an RGB565/RGB5A3 palette, RGB565, RGB5A3, CMPR (the stage dictionaries use all of them); one mip level, same U and V addressing; sizes need not be a multiple of the tile (the padding is skipped).
- **`GXColor.h`**: RGB565 and RGB5A3 to RGBA8, shared by `Gvm` and `Txd`.
- **`GXTexture`**: `decodeCMPR` / `decodeRGB5A3` / `decodeRGB565` / `decodeC4` / `decodeC8` (one level of GX tile data to RGBA8, cropping the padding) and
  `gxDataSize`, shared by `Gvm` (CMPR, RGB5A3) and `Txd`. The C8 tile layout (8x4) is external and not checked by an image.
- **`RwMaterial`**: `readMaterialList` (color and base texture name of each material), shared by `Dff` and `World`.
- **`World`**: `Renderware::readWorld(bytes)` reads a Shadow stage's `.RG1` (name chunk + RenderWare World) into a `RenderWareWorld`: one sector
  (box + submeshes) per BSP leaf with geometry. Only GameCube native sectors are supported: the sector's BinMesh gives the material of each
  mesh and the native data holds GX vertex arrays (position f32x3, color RGBA8, UV0 f32x2, optionally UV1) and one display list of triangle strips per mesh,
  with 8 or 16 bit indices per attribute. Layout decoded from the disc and validated on all 3092 sectors of the 871 stage archives (no
  outside source for the native layout); the collision `.BSP` worlds hold plain data and are read by `CollisionWorld` instead. Hypotheses (marked in the file): vertex color =
  color 0 x material color, strip winding, UV1 (probably a lightmap) ignored.
- **`CollisionWorld`**: `Renderware::readCollisionWorld(bytes)` reads a Shadow collision `.BSP` (plain RenderWare World) into a
  `Physics::CollisionMesh`: one piece per sector with triangles (positions as one array per sector, 4 x u16 triangles, raw u32 "attribute" per
  triangle from UserData; layout decoded from all 614 COLI worlds, winding unknown). The plane sectors are walked but not kept, and the sector's
  collision tree chunk (0x11D) is not read, so the game's order of visiting triangles is not available. `ResourceLoader::addONECollision` appends
  every `.BSP` entry named `*COLI*` of the level's sections (hypothesis: these are the collision worlds), turned by `RenderWareYawDegrees`.
  The port moves bodies against these triangles with its own rule (`CollisionSystem::moveCapsules`: sub-steps + push-out, two sided), not the game's sweep.
- **`Dff`**: `readDff(bytes)` reads frames (with HAnim node id), non-native geometry (positions, normals, first UV set,
  one morph target), the material list (prelit colors times the material color as vertex color (hypothesis: they tint gray textures; almost black ones, all of r, g, b below 32, are ignored as meant for the game's lights, which this engine lacks, e.g. Doom's Eye's body), base texture name) and atomics, into a
  `RenderWareMesh` with one submesh per used material, and the Skin plugin (per-vertex bone indices/weights, inverse bind
  matrices; skin bone i is HAnim hierarchy node i, mapped to the frame with that node id). Each submesh also keeps its material's UV animation name
  (`RenderWareSubmesh::uvAnimName`, from the material's plugin 0x135, see `RwMaterial.cpp`; empty when none; not used by drawing yet). Skipped: BinMesh,
  MatFX (environment map, UV transform), material filter/addressing.
- **`Uva`** (`Renderware::readUvaDictionary` in `Uva.cpp`): RenderWare UV animation dictionary (`.UVA`, chunk 0x2B) into `UvAnimation {name, duration, keys {time, theta, scale, skew, offset}}`. Layout decoded 2026-10-07 from the 27 `.UVA` of `common/CommonEffect.one` (disc; python in the scratchpad, size rule checked on all): animation chunk 0x1B = u32 version 0x100, type 0x1C1, key count, flags (0), f32 duration, 64 bytes (u32 0, name 32 bytes, 28 zero bytes), keys of 32 bytes (u32 unused, time, theta, scale x, scale y, skew, offset u, offset v), u32 unused. The key field order is the RenderWare RpUVAnim order as remembered (hypothesis; the data fit: only offset scrolls). Not read: how the keys become a texture matrix and whether playback loops (see `STH2005_PLAYER_REFERENCE.md` section 21: EFFCHRBALLA scrolls v by exactly 3.0 in 0.667 s, which suggests a seamless loop with wrapping textures).
- **`STH2005::ONE` / `Prs`**: `.ONE` archive ("One Ver 0.60", and "One Ver 0.50" since 2026-10-07: `common/CommonEffect.one`, same header, count and 56-byte entries but a 32-byte name field, so size/offset/always-1 sit at +32/+36/+40; 83 entries decompress to their stated sizes) with PRS-compressed entries, `readFile(name)`; also the
  pooled resource described above.
- **`.CCL`** (Shadow object collision, 1289 entries in the `One Ver 0.60` archives; `STH2005::readCCL` in `CCL.cpp`; `tools/dumpCCL.py`'s `parse_ccl` accepts all 1289 with the same rules and carries the full layout). External, from the Ghidra decompile of the retail `main.dol` (`shadowDecomp/`, untracked; the game's loader `FUN_8040e61c`/`FUN_8040e818`): big-endian, header of 0x20 bytes (size, A = size of section 1, B = size of section 2, 1, 0, `0x3142` whose byte 0x17 `'B'` the game reads as big-endian, 0, 0), section 1 = N records of 16 bytes `{type, pointer (offset from section 1), flags, id}` + a zeroed 16 byte struct + the data blocks, section 2 = the relocation stream of the pointers (N bytes, `'A'` then `'D'` x (N-1), zero padded), section 3 = `{0, 0}` (a group and its name), then the group's name. A record's type is the game's `Range` kind (Sphere 0, Box 1, Capsule 2, Cylinder 3, Plane 4, a Box subclass); the game's constructors copy 4, 10, 9, 9 and 10 floats. Block: Sphere = center, radius; Box/Plane = center, 3 half sizes, 3 angles, 0; Capsule/Cylinder = center, f3, f4, 3 angles, 0 (bounding radius f3 + f4 for a capsule, sqrt(f3^2 + f4^2) for a cylinder; scaling scales f4 with x and f3 with z). Hypotheses: angles in radians (axis order unknown, the game picks it per shape); f4 is the radius and f3 half the length along the shape's z axis. `readCCL` returns `Physics::CollisionShape`s: Sphere form 0, Box and Plane form 3, Capsule form 6 and Cylinder form 11 (a = radius, b = half length, both along the shape's z axis, hypothesis; 11 is this importer's own form so the SADX cylinders, forms 1 and 2, keep standing along y; the lines view draws both, the capsule with caps). Flags go to `attr`; the id, kind/push/damage are dropped/0; their meaning is unknown. Shapes stay in the file's own space (no `RenderWareYawDegrees`). Shadow himself has no `.CCL`: none in `character/*.one`, none named after him (only `SHADOWROBO.CCL`, the android), and `main.dol` names `.CCL` files only for two stage objects (`CN0000ROLLOBJECTNML`, `JG0000FVINEBALL`); observed in a RAM dump of the running game (user's), his body collision is one Capsule of radius 5.5 and zero length (f3 = 0, f4 = 5.5, no rotation) owned by a `CharaColliBody`; where those numbers are stored is not found (see `docs/UNKNOWNS.md`). The same dump also supports f4 = radius and f3 = half length: other capsules there are thin and long (f3 = 40, f4 = 4) and a cylinder is a flat disc (f3 = 0.75, f4 = 22, rotated 90 degrees about x).
- **`Placement`**: `STH2005::readPlacements(bytes)` reads a stage placement file (`sky2`, little-endian: 12 byte header, 44 byte records of position, rotation in degrees, two flag words, type id, sub type, parameter size, then the parameter block). Layout decoded from the four stg0100 files (sizes add up exactly). The type ids are the registry in `main.dol` at 0x8052b080 (external: 286 descriptors, name + id); which model/collision/animation an id loads is not read yet (the stage's `*_gdt.one` holds a `.BIN` recipe per object, undecoded). Only `DebugSetup::addShadowPlacementMarkers` uses it for now: crosses in the collision view (C key), colored by type, with `RenderWareYawDegrees` applied (hypothesis).
- **`RingLine`**: `STH2005::readRingPositions(placement)` gives the positions of the rings one RING record (type 16) stands for: its 20 parameter bytes are `u32 shape, u32 count, f32 a, f32 b, u32`; shape 0 puts every ring at the position, shape 1 (the only one in stg0100) a line of `count` rings, ring i at `(0, 0, -a / count * i)` in the record's frame (rotated about Y then X; the Z rotation does not move a point on that axis). External, from the decompile of the ring object (`FUN_80112cbc`); angles in degrees and the axis order are hypotheses. Shapes 2 and 3 (circle, wave) are not read and throw. `Prefab::layout` (`PlacementLayout::RingLine`, `Placement.json`, written by the generator for the `RING` BIN) makes `Level::setONEEntities` create one entity per ring.
- **`Bon`**: `.BON` skeleton: bone id (matches the DFF HAnim id), name, parent, rest translation/rotation/scale.
- **`STH2005::Model`**: `STH2005::importModel(name, archive, parts)` (adds the mesh to `archive.meshes`, returns its index). `parts[0]` (DFF + BON) is the main model (without a BON it is a static model, e.g. stage objects, and the only part); frames take
  their names from the BON. Each later part with a BON replaces the main model's bone of the same name as its root bone;
  a part without a BON attaches its atomic's frame to the main model bone named in `STH2005::ModelPart::bone`.
  Hypothesis (marked in the file): the game places parts this way. Skin bone frames are remapped with the part's frames.
- **`STH2005::Mtp`**: (a key's marker bit 0 is bit 8 of its frame: observed on DOOMSEYE.MTP, frames 0, 199, 398, 480) `readMtnMotion(bytes, name, bon)` decodes a `.MTN`, one motion in a `.MTP` motion's layout (observed on SPRING00_ANM.MTN: same header, skeleton name and tracks; its size word equals the file size); `MotionKey::mtp` ending in `.MTN` selects it (`ONE::useMotion`). `readMtp(bytes)` lists a `.MTP`'s motions (name, offset, size, an unknown field); `readMtpMotion(bytes,
  name, bon)` decodes one into an `STH2005::Motion`: per bone of the `.BON` its translation, rotation and scale tracks (keys:
  frame, in tangent, tangent, value as half floats; the in tangent equals the tangent except on `sh_slow_skate`'s rotation
  keys with two tangents, whose order is a hypothesis). Layout observed on `SHADOW.MTP`: all 158 motions fit (9 tracks for
  the first node, 12 for the others, three of those unknown and ignored; a track's size is 9 bits).

## Conventions seen in the code
- `struct` everywhere, public members, `this->` on member access.
- Function parameters end in `_` (`position_`, `pId_`); references are prefixed `r`
  (`rCamera_`, `rInstance`).
- Types and namespaces PascalCase; functions and variables camelCase.
- Origin is carried by namespaces, not name prefixes: `STH2005::ONE`, `Ninja::importGvm`, `GameCube::openGCDisc`,
  `Renderware::readDff` (file names keep the origin only where the folder is flat, e.g. `STH2005Keys.h`, `STH2005Motion.h`).
- `#pragma once`; small utilities as header-only `inline` functions.
- Explicit lifetime methods (`init`/`create`/`destroy`) instead of RAII.
- OpenGL 4.5 direct state access (`glCreateBuffers`, `glNamedBufferStorage`, `glBindTextureUnit`,
  `glVertexArray*`), except `Texture::create`, which uses bind-to-edit.
- Errors: `throw std::runtime_error`, with `std::format` messages.
- Comments: one `/* ... */` block before each logical block with non-obvious behavior; evidence labeled as decoded
  from a file, external, or hypothesis.
- Indentation mixes tabs and 4 spaces; braces are mostly on their own line.

## Incomplete or inconsistent (as of this snapshot)
- No lighting. Alpha blending is on (`GL_SRC_ALPHA`, `GL_ONE_MINUS_SRC_ALPHA`, unsorted, texels with alpha < 0.01 are discarded in the `SA` and `STH2005` shaders), but only a texture's own alpha and the vertex color alpha count: an SA material's alpha and its alpha attribute bit are not read, so water and glass stay opaque unless their texture has alpha. The bits of an SA material's attributes that are read are the UV clamp ones (see `SAMdl.cpp`); the flip bits are unknown. Material diffuse colors of SA models are ignored; vertex colors are white. Animation is limited to the idle motions wired in `main.cpp`: SADX at 30 frames/s and Shadow at 60 are hypotheses, and the Euler rotation order of Shadow's motions is unverified (see `ONEInstance.cpp`).
- Shadow's MatFX environment maps and UV transforms are not implemented (the environment textures `pl_bl01n`,
  `pl_hnshd0` are loaded but unused); `.UVA` files are read (`Uva`) but not applied (no UV scroll drawn); the weapon hands/effects are not imported. Only the idle motions are wired (`sh_idle`, `lte_idle`, `rte_idle`); the other hand models (gun, bar, sword) and their motions are not.
- A level's pieces are bound once per texture set (`TextureSet::saBindings`), so two land tables of one set sharing a model would share the first's texlist order. Level start positions and objects (SET files) are not read; the camera starts at a placeholder.
- SADX welds (vertices shared between limbs) are not imported, so gaps can show at Sonic's joints while he animates.
- Textures filter/wrap: `Txd` applies the TXD's value (nearest) while the DFF materials say linear; unresolved.
- Shadow levels: collision is the COLI `.BSP` triangles moved against with the port's own rule (not the game's sweep, see `CollisionWorld`); no fog (`.fog`), lighting or lightmaps (UV1, `_light.bin`); objects are placed (`Level::setONEEntities`) but have no behaviour; no stage start
  positions (the camera starts at a placeholder); what the `.RG1` kinds (`O`, `OS`, `OW`, `A`, `AF`, `K`, `G`, `D` in the entry names) mean is unknown, all are drawn. A level
  loads every section archive of the stage at once. Strip winding and the 90 degree yaw for worlds are unverified.
- `initGlad` in `Utils.h` is unused; `Renderer::init` loads GLAD itself without registering the debug callback.
- `BoneAnimation.h` is empty; SA instances (an SAMotion) and ONE instances (an STH2005::Motion) set a pose.
- `DebugUI` uses ImGui with the GLFW and OpenGL3 backends (`#version 450 core`, the framebuffer's sRGB is switched off while it draws, no `imgui.ini`): the `EntityListPanel`, `InspectorPanel` and `PrefabPanel` along the window's edges (not movable, the vendored ImGui has no docking; resizable since 2026-10-08, nothing built or run: each panel keeps one size as a member (`entityList.width`, `inspector.width`, `prefabPanel.height`), sets it every frame with `SetNextWindowSize` plus size constraints that lock the other dimension, and reads the size back after `Begin`, so dragging the inner edge changes it and the other panels are laid out around it). `EntityListPanel` has a second tab "Editor camera" (look sensitivity, pan, zoom, speed steps, fly speed, boost, fov, planes of `Editor::camera`). 2026-10-08, not run: the left panel is titled "Level" (was "Entities"; its tab "Entities" stays) and has a Collision tab (`CollisionView::drawPanel`, shared with the Debug window; the draw distance slider is in it; the render distance, i.e. the far plane, was already in its Editor camera tab); the Debug window is drawn only while playing. `Editor::loadSettings` / `saveSettings` keep the panel sizes and those camera values in `editor_settings.json` in the working directory: read in `init` (missing or broken file = defaults, values clamped), written in `destroy` only if the content differs from what was read. `EditorCamera::lookSensitivity` (default 0.05 deg/pixel; the editor camera no longer uses `Globals::Mouse::mouseSensitivity` 0.1 directly, `onMouseMove` rescales the offsets before `processMouse`) and one "Debug" window with tabs (Game, Collision, Markers); the camera and physics controls are now the inspector's Camera and Physics tabs. The cursor is visible while the editor is active; a mouse button hold captures it for the mouse look (`Editor::cursorFree` false only then; `mouseCallback` ignores the mouse otherwise), the next position being the baseline. The Collision tab has the switches of the lines view, a draw distance slider and a clickable legend of the values. nlohmann/json is not referenced by CMake.
- `PoolMap::getIdByName` only checks for a missing name in Debug builds.
- `STH2005::ONE` owns GPU data (its meshes and textures) and includes `GPU_Globals.h`.
- Shadow resources are counted per archive only: meshes, `.TXD`s and `switchMeshPart` variants stay until the archive is freed.
