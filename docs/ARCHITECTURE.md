# Architecture

Snapshot of what the code shows as of 2026-10-03. The project is at the importer stage: a window, a free-fly
camera, an OpenGL renderer, and importers that load Sonic (SADX GameCube) and Shadow (Shadow the Hedgehog GameCube)
models with textures straight from the disc images, and play one looping idle motion on each (Sonic's Ninja motion,
Shadow's `.MTP` motions with skinning), and levels drawn from the disc with frustum culling: an SADX land table (Emerald Coast) and Shadow stages (RenderWare worlds, stg0000 / stg0100). No gameplay or lighting is implemented yet.

## Build
- CMake (>= 3.28), C++23, `CMAKE_EXPORT_COMPILE_COMMANDS ON`. Single target `SonicFantasy`.
- Existing `build/` is configured with Ninja, `CMAKE_BUILD_TYPE=Debug`.
- Linux only as written: links the vendored static `third-party/GLFW/lib/libglfw3.a` (loads X11 via dlopen), `pthread`, `m`, `GL`, `dl`.
- New `.cpp` files must be added to `add_executable` in `CMakeLists.txt` by hand.
- Include directories are `src` and every folder below it that holds headers (`src/Objects`, `src/Graphics`,
  `src/Graphics/Resources`, `src/Graphics/InstanceData`, `src/Importers`, `src/Importers/GameCube`,
  `src/Importers/Ninja`, `src/Importers/STH2005`, `src/Importers/Renderware`, `src/Loading`, `src/Keys`, `src/Misc`), so headers are included by bare name
  (`"Camera.h"`, not `"Objects/Camera.h"`). A new folder needs adding to `target_include_directories`.
- The executable runs with cwd `build/` (`.vscode/launch.json`, lldb). The `CopyShaders` target copies the repo's
  `Shaders/` to `build/Assets/Shaders` on every build. Other `Assets/` paths (`Assets/Models`, `Assets/Textures`) are
  read relative to `build/` but nothing copies them.
- The disc images are read from `Disks/Shadow2005.iso` and `Disks/SADX.iso` (`Constants.h`), i.e. `build/Disks/` (the executable runs with cwd `build/`).
- `.gitignore` excludes `build/`, every folder starting with a dot, and `sadreamcasttools/`.
- Lua 5.4.7 is vendored in `third-party/lua` (MIT; the interpreter and compiler programs left out) and built by `CMakeLists.txt` as the static library `lua`, compiled as C++ so a Lua error is a C++ exception, `LUA_USE_POSIX` only (no dlopen). The repo's `Scripts/` folder is copied to `build/Assets/Scripts` on every build by the `CopyScripts` target, like the shaders.
- `ENGINE_DEBUG` gates the validity checks in `Pool`/`PoolMap` (including the missing-name error in
  `PoolMap::getIdByName`); `CMakeLists.txt` defines it for Debug builds.

## Runtime flow
1. `createWindow` (`Utils.h`): GLFW, OpenGL 4.5 core, debug context, cursor disabled,
   framebuffer-size and cursor-pos callbacks.
2. `Graphics::renderer.init()`: loads GLAD, enables sRGB framebuffer, depth test,
   back-face culling (CCW front), loads the `Default` shader and builds the debug floor mesh.
3. A `Camera` is pushed into `Globals::Game::cameras`; index 0 is the player camera.
4. `main.cpp` adds the `SA` and `STH2005` shaders, opens both discs into `Globals::Discs` (they stay open), creates the level (a `Level` and `setONEGPUInstance(oneShader, Stg0100Level)` for a Shadow stage, camera placed next to it; the SADX `setSAGPUInstance(saShader, EmeraldCoastLandTable, EmeraldCoastTextures)` is commented out), then creates each character:
   an `Entity` (position only) and its instance from the keys in `ResourceKeys.h`: `setSAGPUInstance(saShader, SonicMesh,
   SonicTextures)` then `playSAMotion(SonicIdle)`, `setONEGPUInstance(oneShader, ShadowMesh, ShadowTextures)` then `playONEMotion(ShadowIdle)` and the two hand motions. Nothing is imported before that: the
   instance finds or loads what its keys name (see Entity, TextureSet, STH2005::ONE below) and holds one user of it.
5. Loop: compute `Globals::App::deltaTime`, poll events, `processInputs()`, `Entity::update(deltaTime)` for every live
   entity (advances SA and ONE motions), `renderer.run(cameras[0])`: clear,
   bind the camera UBO at binding 0, call `Level::draw(camera)` for every live level (the debug floor is commented out), then `Entity::draw` for every live entity. Then `debugUI.draw(cameras[0])` (ImGui, a separate pass: a window with the camera position) and `glfwSwapBuffers` in `main.cpp`.
6. `renderer.destroy()`, `destroyWindow()`.

## Core pieces
- **Globals** (`Globals.h`): `inline` variables in `Globals::App` (window, size, frame timing), `Globals::Game`
  (cameras, `entities`, `levels`), `Globals::Discs` (the two opened `GCDisc`s), `Globals::Mouse`. `Graphics::renderer` and the `basicMeshes`/`textures`/
  `textureSets`/`textureBindings`/`shaders`/`saMeshes`/`oneArchives` pools and instance pools live in `GPU_Globals.h`.
- **Pool<T> / PoolMap<T>**: deque-backed slot storage with generational `PoolId
  {id, generation}`, free-slot reuse, `alive` flags. `PoolMap` adds name lookup (`nameToId`; adding a duplicate name
  keeps the first id; `remove` drops a name only if it points to the removed slot). `remove` calls the element's `destroy` if it has one. The storage is a `std::deque`, so `add` never moves existing elements: a reference from the pool (`getEntity`) stays valid until that slot is removed and reused. Across anything that removes (a behaviour or callback that destroys entities), keep the `PoolId` and look it up again. `UninitializedPoolId` in `Constants.h`.
- **Camera**: yaw/pitch mouse look (pitch clamped to +-89 degrees), 45 degree perspective,
  `nearPlane` (1, for depth precision) / `farPlane` (50000 set in `Camera.h`; a slider in the debug UI's Camera tab, up to 500000, changes it and the projection). `farPlane` is also the one render distance: levels stream by it and entities are drawn and active within it. `speed` (50 in `Camera.h`) is the free-fly speed in
  units/s and `speedUp` (3) multiplies it while Left Shift is held (`processInputs`). When the window regains focus the next
  cursor position becomes the mouse baseline (`focusCallback`), so the camera doesn't jump. `frustumPlanes()` returns the six view
  frustum planes (inside = `dot(normal, p) + d >= 0`) and `sphereInFrustum` tests a sphere against them. `view` and `projection` are uploaded to a UBO (`std140`,
  `CameraData { mat4 view; mat4 projection; }` at binding 0) on every change.
- **BasicMesh**: interleaved `Vertex` buffer (locations 0 position `vec3`, 1 normal `vec3`,
  2 uv `vec2`, 3 color `vec4`, 4 bone indices `u8vec4` (integer attribute), 5 bone weights `vec4`; both zero unless skinned), optional `uint32_t` index buffer, drawn as `GL_TRIANGLES`
  with whatever program is bound. Manual `destroy()`.
- **Shader**: `Shader(name)` loads `Assets/Shaders/<name>/vertex.glsl` and `fragment.glsl`, throws
  `std::runtime_error` with the GL log on failure, caches the `model` uniform location.
  `HasTextureLocation` (`Shader.h`) is the fixed location of the `hasTexture` uniform that textured draws set.
- **Texture**: CPU `pixels` (RGBA8) filled by an importer, uploaded by `create()` as `GL_SRGB8_ALPHA8`, no mipmaps.
  `filter` and `wrap` fields (default nearest / clamp to edge) are applied by `create()`, and `mipmaps` (default true) first gives fully transparent texels the color of their opaque neighbors (`bleedTransparentColor`, alpha stays 0), then generates the full mip chain from level 0 and makes the minification filter mipmapped (`GL_NEAREST_MIPMAP_NEAREST` or `GL_LINEAR_MIPMAP_LINEAR`). Manual `destroy()`.
- **Entity**: `sourceEngine` (`SA_NINJA` or `STH2005_ONE`) selects which instance pool `instanceId` refers to.
  An entity is created first and has no instance (`UninitializedPoolId`, not drawn) until `setSAGPUInstance` /
  `setONEGPUInstance` attaches one, created from resource keys (only one of the two, once; a second call throws;
  textures are optional, the overload without them is untextured). `draw` calls the instance's `draw` with `translate(position) * rotation` (`rotation` is a world-space matrix, identity by default, set with `setRotation`), cached in `transform` and rebuilt only when `transformDirty` (set by `setPosition` / `setRotation`, and initially); change them with the setters.
  `Entity::destroy` (run by `entities.remove`) removes the instance, which releases its texture set or archive.
  `changeActiveMesh(key)` / `changeActiveTexture(key)` (ONE instances only, otherwise they throw) switch the instance to
  another mesh or `.TXD` entry; the key's archive has to be the instance's, and what is not loaded yet is loaded.
  `switchMeshPart(previous, desired)` replaces one `STH2005::ModelPart` of the active mesh's recipe with another (the parts are
  named in `ResourceKeys.h`), so the combinations need no keys of their own: the mesh with that part switched is built on
  first use (`STH2005::ONE::switchPart`, named `<mesh>|<previous dff>><desired dff>`), found again when the recipe exists, and
  the pose is dropped like in `changeActiveMesh`.
  `playSAMotion(key)` / `playONEMotion(key, loop = true)` (SA / ONE instances only) make the instance loop a motion (a ONE motion with `loop = false` plays once and holds its last frame); `update(deltaTime)` advances it.
  The instance's `draw` binds its shader, calls the mesh's `use()` (lazy GPU upload), binds textures and draws.
  `ONEInstance`s additionally rotate 90 degrees about +Y (`RenderWareYawDegrees` in `ONEInstance.cpp`), a
  value derived from Shadow alone and applied to every RenderWare model.
- **SAMesh**: node hierarchy (`parent` index, -1 = root, parents stored before children), rest `localTransform` per
  node, submeshes that own their `BasicMesh` directly plus a `textureIndex` (the material's texture id, `SANoTexture`
  if none). A mesh is named `<rel>@0x<offset>` (`SAModelKey`), imported on demand from the SADX disc, and has a `users` count: at 0
  `releaseSAMesh` removes it (and the bindings sets keep for it). The relocated `.rel` it came from is kept in `relModules`
  (a `RelModule`: the bytes plus a count of live meshes imported from it) so the next model of that module is not read and
  relocated again; the bytes are freed when the last of those meshes is removed. **SAInstance**: `saMeshId`, `shaderId`, `textureSetId` and
  `textureBindingId` (both `UninitializedPoolId` = untextured) plus `nodePose` (one matrix per node). It holds one user of its
  mesh and of its set. Nodes also keep their rest position, rotation (BAMS), scale and flags; `composeNinjaTransform`
  (`SAMesh.h`, rotation order a hypothesis) builds both the rest transform and animated poses.
- **Sonic's collision** (external, from the Ghidra pseudocode of `_Main.rel`; that the table is Sonic's is a hypothesis): His table is `_Main.rel` 0x354E10 (`SAShapes_Main_80754E10` in `SAShapeKeys.h`), 2 entries: entry 0 form 7 (box-like, half sizes 4, 4, 0.65) at (0, 1, 0), entry 1 form 1 (cylinder-like, a 3.5, b 10) at (0, 2, 4). No key names it and `main.cpp` does not load it: the collision system only moves an entity by sphere and capsule shapes, so `addSonicShape` gives Sonic one sphere of the size and height the game's per-character record gives (Sonic: collision size 4, center height 5.4, `_Main.rel` 0x2C61E8), moved down by 5.3, the height of the model origin above his feet (observed, from you), because the game's positions are hypothesized to be at the feet. The game rewrites entry 0 every frame (center, and the damage byte from the player's state), none of which is reproduced.
- **Collision behaviours** (`Keys/BAKeys.h`, `Objects/BABehavior.h`, `Objects/BABehaviors.*`): our own convention for what a collision is and does, not either game's. A *tag* is a category (`BATagKey` names it; `Globals::Game::baTags` is a `PoolMap<BATag>`, only the name and so the `PoolId` matter). A *behaviour* (`BABehaviorKey`; `Globals::Game::behaviors`, a `PoolMap<BABehavior>`) is a bag: `tags` (what it is), `availableCollisions` (a set of tag ids it is stopped by) and `availableInteractions` (tag id to `BAInteraction`, a function `(parentEntity_, contactEntity_)`). For an overlap each side looks the other's tags up in its own two maps; with no match on either side it is skipped, so nothing branches on what the other is; a collision rule is only "there is one" (push out). A script finds a tag or behaviour by name (`BABehaviors::findTag` / `find`) and keeps the `PoolId`. `Globals::Game::baBehaviors` (`BABehaviors`, `init()` before anything is loaded) describes and fills both pools with the built-ins (tags `Solid`, `Pickup`, `Hazard`, `Death` and `Body`; behaviours `Solid`, `Pickup`, `Hazard`, `Death`, each with its one tag and no rules, `Body` with the `Body` tag that collides with the `Solid` tag, and `None`, `Passable` and `Object` with no tags) and, from the hardcoded remaps of `BAKeys.h` (`BARemapShadowLevel`, `BARemapSADXLevel`, `BARemapSADXShape`, `BARemapShadowShape`: raw value to behaviour), gives a collision its behaviours when `ResourceLoader` loads it (`BABehaviors::resolve`): `Physics::Collision::behaviorByValue` / `fallbackBehavior` per raw triangle value (`behaviorOf`) and `CollisionShape::behavior` per shape. `Collision::entityId` is the owning entity (`Entity::selfId`; none for a level's), the parent an interaction gets. The collision system compares `PoolId`s and tags only: a triangle is solid for a shape if the shape's behaviour `collidesWith` the triangle's; the interactions of both sides are called once per gameplay tick after the move, parent = the entity that owns the side's collision (`UninitializedPoolId` for a level), contact = the other. Shadow: attributes 0x2, 0x202, 0x20001, 0x8, 0x28001 are `Solid`, 0x10 `Passable` and 0x20 `Death`, any other `None` (observed, from you); SADX: every flags value is `Solid` except 0x00200001, `Passable` (observed, from you; the bits are unknown); every object shape is an `Object` (no tags until given some). The hand-made character shapes are `Body`s, and a moving entity's shape without a behaviour counts as one. Entity against entity (`updateEntityContacts` in `CollisionSystem.cpp`, after the moves): shapes are reduced to capsules (sphere, forms 6 and 11, and forms 1 and 2 as the inscribed capsule: hypothesis) or boxes (forms 3, 4, 5, 7) the way the lines view draws them; a physics entity's capsule or sphere is pushed out of the shapes of other entities it collides with (that entity only is moved), and the interactions of an overlap are called last. Only shapes whose behaviour has any rule start a test. The debug lines legends (Collision tab, Level and Entities) show each raw value with the name of its behaviour.
- **Entity behaviours and the GameplaySystem** (`Gameplay/EntityBehavior.h`, `Gameplay/GameplaySystem.*`): `Globals::Game::entityBehaviorTypes` is a `PoolMap<EntityBehavior>` (a name and a `pBehave(PoolId entityId_)` pointer; `addEntityBehavior` in `API.h`). `Globals::Game::entityBehaviors` is a `Pool<EntityBehaviorSet>`: one record per entity that has behaviours (`{entityId, behaviorIds}`, a stack in the order given), made by `giveEntityBehavior`; the `Entity` holds its id (`behaviorSetId`) like its other handles and removes the record in `destroy`. `Globals::Game::gameplaySystem.update(deltaTime)` runs the records' behaviours in order, on copies, once per gameplay tick: `tickRate` (60, a guess) times a second through an accumulator (at most `maxTicksPerFrame` ticks a frame, the rest of a long frame dropped), so a frame can run none or several. A tick is the fixed-step simulation: the destroyed entities are removed, the active entities' `previousPosition` is kept (`SpatialIndex::updateActive` sets `Entity::active` and `SpatialIndex::activeEntities`: active = within `farPlane` of camera 0 by its bounding sphere, distance only, or `Entity::behaviorNotCulled`, which `attachPlayer` sets for the player; `GameplaySystem::cullFarEntities` turns it off; `PhysicsSystem::update`, the collision system's moves and `updateEntityContacts` iterate the active list and the behaviours skip inactive entities, so the render distance is the one limit for drawing and simulating), the behaviours run, then `PhysicsSystem::update(tickTime)` and `CollisionSystem::update()` (so the movement and the interactions are per tick, not per frame). What is drawn is `Entity::renderPosition()` / `renderRotation()`: by `GameplaySystem::interpolationAlpha()` (the accumulator's fraction of a tick) the state of the latest tick is carried on (`GameplaySystem::extrapolate`, the default: by a physics entity's velocity, otherwise the last tick's change, so nothing is a tick behind but a move that stops can overshoot by up to a tick) or the entity is mixed from `previousPosition` / `previousRotation` (off: smooth, a tick behind); rotations go through quaternions. The simulation moves entities with `Entity::moveTo` / `turnTo` (keep the previous ones), `setPosition` / `setRotation` teleport. The debug lines, the text labels and the follow camera use the render position (the collision itself uses the tick's `position`). The Game tab has the extrapolate switch. The system runs each frame right after `processInputs()` and before the level and entity updates (`main.cpp`). `Entity::markForDestroy()` puts the entity in `Globals::Game::markedForDestroy` (a `Pool<PoolId>`) and `GameplaySystem::destroyedCleanUp()` removes them (`Entity::destroy` runs) at the start of every tick; `Entity::selfId` is the entity's own id (set by `addEntity`). Nothing uses it yet. Not to be confused with `BABehavior`, what a collision does.
- **Scripting** (`Scripting/`, `Scripts/`): gameplay is written in Lua over the C++ engine (decided with the user: one physics and collision system for both games stays in C++; every game rule, the player's movement included, is a script). `main.cpp` calls `Scripting::init()` and loads `Scripts/main.lua`, which includes `sadx/main.lua` and `shadow/main.lua`, defines the global `attachPlayer(entity)` (called once for Sonic and once for Shadow; it picks `attachSonicPlayer` / `attachShadowPlayer` by the entity's name, the first one attached is the active player, only the active one reads the keys: `state.active`) and the behaviour `PlayerSwitch` (J switches the player: the characters stay where they are and `sf.followCamera(entity)` / `Globals::Game::cameraTarget` tells `main.cpp` which entity the follow camera sits behind; R puts every player back at the position it had when attached); `spawnSAObject` calls the script global `setupObject(entity, name, placement)` for every object it makes and `main.cpp` the global `attachPlayer(entity)` (`Scripting::setupObject` / `attachPlayer`; a script that does not define one is skipped). A script sees the engine through `sf` (list in the header comment of `ScriptAPI.cpp`): entities, tags and collision behaviours (`sf.collisionBehavior(name, {tags, collidesWith, interactions})`, interactions are `fn(parent, contact)`), entity behaviours (`sf.behavior(name, fn(entity))`, `sf.give`), bodies (velocity and the ground contact the collision system records in `PhysicsBody`: `grounded`, `groundNormal`, `groundSurface`, `touchingWall`, `wallNormal`), events, input, rings. Entities, tags and behaviours are integer handles (`PoolId` packed, `sf.none` = -1). What an object remembers is a plain Lua table, `sf.state(entity)` (`Entity::scriptStateRef`, released by `Entity::destroy`); the C++ `EntityState` bag is only for the C++ behaviours. `EntityBehavior::scriptFunction` and `BAInteraction::scriptFunction` are Lua registry references called by `GameplaySystem::tick` and the collision system (a `BAInteraction` is a C++ function or a script function; two are equal if they are the same one, which the once-per-pair dedupe uses). Libraries open: base, table, string, math, utf8, coroutine (no io, os, package, debug, dofile, loadfile). Lua numbers are doubles: bit-exact floats are not a goal (observed behaviour is); `LUA_FLOAT_TYPE` could make them 32-bit later. Not scripted yet: the camera, spawning from a script, a reload key, and contact points or normals for interactions (they get only parent and contact).
- **SADX gameplay** (`Scripts/sadx/`, in Lua; the C++ placeholders that came first are removed): `main.lua` includes `objects.lua` (the tags `Ring`, `Spring`, `DashPanel`, `Enemy` and one collision behaviour each, with an interaction for the `Body` tag, plus `Pickup` for rings and `Hazard` for enemies; the entity behaviour `Cooldown`; `setupObject` picks by the key's name: `RING`, `SPRING` / `SPRINGB`, `O AXPNL`, `E SARU` / `E SAITO` / `E AMEMB`, giving the shapes the behaviour and filling `sf.state`) and `player.lua` (the behaviour `Player`, `attachPlayer`). Decoded (external, pseudocode): the dash panel (`scale.x` speed, `scale.y` disable time, defaults 14 and 60, the velocity (speed, 0, 0) turned z, x, y - 0x4000 by the record's angles, no relaunch until the countdown ends; units per frame at 60 a second and frame = tick are hypotheses). Placeholders (numbers made up, in each file's constants): the ring (counted, removed), the spring (launch along its up axis), the enemies (a player in the air, by `sf.grounded`, destroys them and bounces, otherwise it loses its rings and is knocked back) and the player controller (W A S D move relative to the camera with acceleration and friction, velocity kept in the plane of the ground under him, Space jumps from the ground; in the debug mode (Tab) those keys fly the camera instead and Sonic ignores them; outside it the camera follows Sonic from behind, placeholder distance, `updateFollowCamera` in `main.cpp`; `Scripting::attachPlayer(sonicId)` in `main.cpp`). The debug UI's Game tab shows the rings and a switch that logs game events to stderr. `EntityState` (`Globals::Game::entityStates`, `Entity::stateId`, `entityStateOf`) is a plain bag the C++ placeholders used and nothing uses now.
- **Presentation from gameplay** (`Entity::animationIntent`, `Gameplay/GameEvents.*`): behaviours change game state only and never call the renderer, since a frame can run no tick or several. `changeAnimation(entityId, key[, loop])` (`API.h`) writes the entity's wanted motion (`AnimationIntent`: a pointer to a static `SAMotionKey` or `STH2005::MotionKey` and a loop flag, last write wins, harmless every tick); `Entity::update` plays it once a frame when it differs from `appliedAnimation`. One-shot things (a sound, an effect) are `GameEvent`s (a name, an entity or none, a position) posted with `postGameEvent` into `Globals::Game::gameEvents`; `main.cpp` calls `drain()` once a frame after the collision system, which drops events about entities that are gone, logs them if `logEvents` is on and hands each to the handler registered for its name (`addGameEventHandler`); there are no handlers yet. Posted: `RingCollected`, `DashPanelLaunch`, `SpringLaunch`, `EnemyDefeated`, `PlayerHurt`.
- **Culling** (`Objects/SpatialIndex.*`, `Graphics/Resources/BoundingSphere.h`, `Entity::draw`): each model has a bounding sphere computed once from its rest pose with a margin (`SAMesh` / `RenderWareMesh::computeBounds`, `Entity::localBounds`). `Globals::Game::spatialIndex` (`SpatialIndex`) holds the *static* entities (an instance, no physics) in a bounding volume hierarchy built by `rebuild()` (called once the level's entities exist, `main.cpp`; a static entity is assumed not to move, and a removed one is skipped by its slot and generation) and the *dynamic* ones (the others: entities with a physics and everything created after the rebuild) in a flat list. `Renderer::run` asks the hierarchy for the static entities inside the frustum and within the far plane (the render distance), walks the dynamic list, and `Entity::draw` tests each sphere again; before the first `rebuild` every entity is drawn as before. The same index decides which entities are active (`SpatialIndex::updateActive`, once per gameplay tick: within the draw distance of the camera, distance only, or `Entity::behaviorNotCulled`; see Entity behaviours below): physics, collision and behaviours run for those only. Each entity brings its own sphere, `Entity::bounds` (its model's sphere and one around its collision shapes enclosed in one, a point with neither), recomputed by `Entity::refreshBounds` in every setter that attaches or changes a model, collision or physics (code that sets `collisionId` by hand calls it too, as `DebugSetup` does); that marks the index dirty and the next query rebuilds it. An entity with a physics or `behaviorNotCulled`, or made after the first `rebuild`, is kept in the dynamic list (later rebuilds keep it there); all others are static items. Not built yet: the contact broadphase from the index (the collision system keeps its per-tick grid), and sorting the visible set by shader / mesh / texture (design in `docs/RENDER_DRAW_LIST_DESIGN.md`).
- **Level** (`Objects/Level.h`, `Globals::Game::levels`, a `PoolMap`): the counterpart of `Entity` for static world geometry: `sourceEngine`,
  `instanceId`, `position`; no instance until `setSAGPUInstance(shader, SALandTableKey, SATextureSetKey)` (SADX) or
  `setONEGPUInstance(shader, STH2005::LevelKey)` (Shadow), not drawn before that. `Level::destroy` removes the instance, its collision and its entities. `Level::setSAEntities(shader, SALandTableKey)` is the SADX counterpart: an `Entity` per SET record whose type the key's table lists (model, textures, collision shapes (`Entity::setSACollisionShapes` takes several tables) and the first motion, looping; rotation from the BAMS angles: Rz * Rx * Ry by default (external, the decompile of `_Main.rel` and `_Stg01.rel`: the Ninja rotate calls of the palm tree display and 92 other functions run z, x, y on the angles at +0x14 x, +0x18 y, +0x1C z of the task), or the object's own recipe (not used when its function is shared with another object, `SAEntityKey::rotation`, `SARotationStep`: axis, which angle, addend, negate; the generator reads them from the calls to main.dol's rotate functions 0x8004AFDC z / 0x8004B3E0 x / 0x8004AF5C y in the object's machine code, following r4 back to the task's angle: e.g. the dash panel turns about y by the angle + 0x8000, the launch board z, y, x; a recipe is only taken when it turns about all three axes by the task's angles: 7 of them); an SADX entity's collision shapes are drawn turned by its rotation too (centers and angles), and an SADX form 6 is drawn as a capsule along y (Shadow's form 6 is along z; observed on the palm trees' shape, a = 3, b = 20, center (0, 20, 0)); no scale), a marker for the others; enabled by the commented lines of the Emerald Coast block in `main.cpp`. `Level::setONEEntities(shader, LevelKey)` (Shadow) creates an `Entity` for every record of the key's placement files (`readPlacements`) whose type the key's table lists: first model, textures and collision shapes of its `EntityKey`, at the record's position with `RenderWareYawDegrees` applied and the level's position added (hypothesis). `EntityKey::layout` says what a record makes: one entity per model of the key's first variant (`Single`: the `.BIN`'s first info, e.g. the cage and its bars), one per ring (`RingLine`, see `RingLine`), or one per model of the variant the record names (`Variant`: the stage art objects, whose first parameter u32 is, as a hypothesis, the index of the `.BIN`'s info; `EntityKey::variants` holds the model indices per info and the info's collision goes to the first). The first motion the key lists is played on the first model: looping for enemies and characters (`EntityKey::loopMotion`), once holding its last frame for the rest (placeholder until there is behaviour; a motion that can't be read is reported). Each entity gets the record's rotation (`Entity::setRotation`, angles in degrees applied about Y, X, Z in the game's space and conjugated by the yaw; a ring takes only its Y angle: the ring code copies one angle into each ring; all hypotheses). Not used yet: the records' other parameters, an entity's other models (outside `Variant`), how a model with a parent in its `.BIN` attaches to it, `.UVA`. A record whose type the key does not list (invisible triggers like SETCOLLISION and HINT COLLISION, effects like FIRE and PARTICLE) gets a marker in `Graphics::collisionView.markers` instead: a cross colored by the type id (`CollisionView::colorOf`), drawn even with the collision view off, and listed by the debug UI's "Markers" window with the type's name (`LevelKey::typeNames`) and count. An object that fails to load is skipped with a message on stderr. `Stg0100Level` places all four of its placement files (cmn, nrm, hrd, ds1); that nrm / hrd / ds1 are alternatives of different missions is a hypothesis and is not handled, so objects of every mission show.
  Both level instances stream their pieces by the camera with the same rule (`LevelStreaming.h`, `levelPieceAction`): a piece
  (a bounding sphere) within `farPlane` has its GPU buffers uploaded and is drawn if in the frustum, one further than
  `farPlane` x 1.5 (`UnloadDistanceFactor`, a guess) gives its GPU buffers back; the CPU data stays. Pieces are the games' own chunks
  (no splitting).
- **SALevelInstance** (`saLevelInstances`): one `SALevelPiece` (an `SAInstance` plus the COL's bounding sphere) per visible piece of a
  land table, created by `Loading::addSALevelInstance`: it reads the land table (`readSALandTable`) from the cached relocated `.rel`,
  finds or loads the `.gvm`, resolves the land table's texlist names against `TextureSet::names` (a missing name throws), and imports
  each piece (its COL's model, an `SAMesh` named like any other) with an `SAInstance` bound through that resolved order. Only COLs with
  surface flag bit `0x80000000` are imported (hypothesis: the rest are collision only) and a piece whose submeshes all use a texture
  in `SALandTableKey::skippedTextures` is dropped again (Emerald Coast skips the baked `m8_shadows`). Unloading calls `SAMesh::destroy`.
- **ONELevelInstance** (`oneLevelInstances`): the pieces (`ONELevelPiece`: bounding sphere of a world sector's box + its submeshes, each a
  `BasicMesh` and a Texture pool id) of every `.RG1` world of a stage's section archives, created by `Loading::addONELevelInstance`:
  it finds or loads the stage's texture archive (`stgNNNN_texCM.one`, one user held, a `.TXD` entry of it), reads each section archive
  from the Shadow disc (transient, not pooled), decodes its `.RG1` entries except those whose name contains a part of `LevelKey::skippedEntries` (stg0100 skips `_D_` and `_G_`, probably sky domes: huge low-poly spheres) (`Renderware::readWorld`) and looks every submesh's
  texture name up in the dictionary (a missing name throws, so the names are case sensitive). The pieces own their data (not
  pooled); `draw` applies one model matrix, the base rotated by `RenderWareYawDegrees` (hypothesis: also right for worlds), with the
  `STH2005` shader, `skinned` off. Unloading calls `BasicMesh::destroy`. A level uses a `.TXD` from another archive than its meshes
  (unlike a character's `ONEInstance`, which is restricted to one archive).
- **SAMotion** (`SAAnimation.h`, `saMotions`, a `PoolMap` named `<rel>@0x<offset>`): a Ninja motion, frame count plus
  position/rotation/scale keys per model node. Loaded from an `SAMotionKey` (`.rel`, offset, node count from SA Tools) through
  the `relModules` cache by `Loading::playSAMotion`, which checks the node count against the model; `users` counts the
  instances playing it. `SAInstance` holds `currentSAAnimation` and `animationFrame`; `update` advances at 30 frames/s
  (hypothesis), loops, and samples keys like the game's linear interpolation (SADX decomp: holds the last key, rotations
  take the short way in whole BAMS), with rest values for unkeyed channels and the node's NoPosition/NoRotate/NoScale
  flags ignored, and fills `nodePose`.
- **RenderWareMesh**: `frames` (parent index, rest `localTransform`, HAnim `boneId`, `name` from a `.BON`), `atomics`
  (a frame index plus submeshes, each a `BasicMesh` and a `textureName`; a skinned atomic also has `skinBoneFrames` and
  `inverseBindMatrices`). `use()` uploads submeshes.
  **ONEInstance**: `archiveId`, `shaderId`, `meshIndex`, `textureDictionaryIndex`, `bindingIndex` (indices into the
  archive, `STH2005::NoIndex` = untextured), `framePose` overrides the rest
  transforms; `draw` computes frame world matrices and draws every atomic: a skinned one with `skinned` set and
  `world[skin bone frame] * inverse bind matrix` per bone uploaded to `Renderer::boneBuffer` (`MaxSkinBones` = 256), an
  unskinned one with `model` = its frame's world matrix. `motions` are the playing motions (`playMotion(key)`, one per skeleton,
  decoded on first use into `STH2005::ONE::motions`); `update(deltaTime)` advances them at 60 frames/s (hypothesis), loops over
  the motion's last frame and fills `framePose`: every frame at its rest transform, the frames named like a motion's bones at
  `translate(T) * rotation(R) * scale(S)` sampled with cubic Hermite (tangents = slope per frame, hypothesis; a key's in tangent arrives at it, its tangent leaves it). Euler order

  on demand by `addSAInstance` if not loaded. `users` counts the instances using the set; at 0 `TextureSet::destroy`
  removes its textures (`glDeleteTextures`) and bindings. **TextureBinding** (`textureBindings`): an SAMesh's submeshes

  instances (the set keeps `saBindings`, one per mesh): a `textureIndex` past the set's end throws. The same struct is the
  per-submesh table of a Shadow binding. If creating an instance fails halfway, what that call loaded is removed again.
- **STH2005::ONE** (`oneArchives`, a `PoolMap` named by disc path, Shadow only): the archive's bytes and entries plus what

  (`.TXD` entries, decoded on first use by `useTextureDictionary`, each as ids plus a name lookup) and `bindings` (per

## Importers
All importers take bytes already in memory (or a path for `.sa1mdl`), throw `std::runtime_error` on anything outside
what they support, and carry the evidence for each layout in a comment (decoded from a file, external source, or
hypothesis). None of them contains a model, texture, bone or archive-entry name: those come from the resource keys in `ResourceKeys.h`.
- **`GCDisc`**: opens `.iso`, reads the file table, `readFile(path)` reads one file on request.
- **`Rel`**: applies a `.rel`'s relocations against itself; pointers then equal file offsets. A `SaCompGC` compressed module is decompressed first.
- **`SaComp`**: `isSaComp` / `decompressSaComp`: the bit-stream LZ77 of the 20 compressed SADX `.rel` files (`_Stg*`, `_Adv*`, `_B_chaos6/7`,
  `_Minicart`, `_Shooting`). Algorithm external (X-Hax/SACompGC, derived from the game's own routine); output checked on four modules.
- **`SALandTable`**: `readSALandTable(bytes, offset)`: COL pieces (model offset, surface flags, bounding sphere) and the texlist names.
  Layout decoded from `_Stg01.rel` and checked on every land table in SA Tools' GC_SADX INIs. Animated parts are not read.
- **`SASet`**: `Ninja::readSAPlacements(bytes)` reads an SADX SET file (`Set0100S.bin`): u32 count + zeroed header up to 0x20, then 32 byte records `u16 type, s16 rotation[3] (BAMS), f32 position[3], f32 scale[3]` (the low 12 bits of the u16 are the type and the top 4 flags, 8 on 54 records of Set0100S, meaning unknown; the scale holds parameters, not a scale: values like 1.9, 60.0, 12.3 that differ per object kind. External, the decompile of `_Main.rel` and `_Stg01.rel` (`sadxDecomp/decompiled_stg01/`, built by `tools/decomp/sadx/runStg01.sh`): none of the Emerald Coast decor objects' code (palm trees, railings, coral ...) reads the task's scale fields (+0x2C, +0x30, +0x34); the shared objects that do use them as parameters, differently each: SPRING scales x by `scl.x` in some state, the dash panel divides by them, spikes scale by 1 + `scl.x/y`, and the collision-only objects (WALL, C CUBE, C SPHERE, C CYLINDER) take their shape size from them. So no uniform scale is applied; the size matches exactly on Set0100S (788 records). The type indexes the stage's object list.
- **`tools/sadxLiveTasks.py`** reads a Dolphin RAM dump of SADX (`sadxDecomp/mem1.raw`, Memory window > Dump MRAM, Emerald Coast act 1) and lists, for each SET record that is a live task, the exec / display / destroy functions as offsets into `_Stg01.rel` / `_Main.rel`, with the live angles and height next to the record's. Observed on the first dump (68 tasks): 48 of 62 matched records have the same position, angles and scale as their SET record (the game does not change them; parasols drop 1 unit to the ground), so the records' rotation is used as is, and the display function of each type is known exactly (`genSAEntityKeys.py` reads the models and rotation calls inside it).
- **`SAMdl`**: `importSAModel(name, bytes, rootOffset, bigEndian)`. One `SANode` per NJS_OBJECT (depth first),
  one `SASubmesh` per meshset, one vertex per poly corner with position and UV (255 = 1.0). A submesh keeps
  its material's `texture id & 0xFFFF` as `textureIndex`; the `TextureSet` is applied when an instance is created, not by the importer; `rootOffset` comes from an `SAModelKey`. Bit 23 (0x800000) of the material attributes is read as double sided (`SASubmesh::doubleSided`, drawn without back-face culling; hypothesis: Ninja's NJD_FLAG_DOUBLE_SIDE as remembered, unchecked on a file). Normals, vertex colors, material
  diffuse/specular and attributes are not read. Limits: Ninja Basic only, non-DX struct sizes. An NPoly meshset (type 2) is read like a strip (observed on Kiki's). An attach with no materials (the collision model "Pier Collision") is read untextured.
  Hypotheses (marked in `SAMdl.cpp` / `SAMesh.h`): rotation order, triangle winding, quad/strip corner order, texture id = index into the `TextureSet`'s file order.
- **`SAMotion`**: `readSAMotion(bytes, offset, nodeCount, bigEndian)` reads an NJS_MOTION (position, rotation, scale
  channels, linear only; anything else throws). Layout from SA Tools, confirmed on Sonic Idle.
- **`Gvm`**: `importGvm(setName, bytes)` decodes a GVM archive into the Texture pool (linear filter) and a new `TextureSet`
  (archive order); returns nothing. Limits: header flags `0xF` only, CMPR and RGB5A3 only, mip level 0 only, sizes in whole tiles.
- **`Txd`**: `importTxd(bytes)` decodes a RenderWare texture dictionary of GameCube textures into the Texture pool by
  name and returns the ids (in order and by name) for the caller to keep, with the file's own filter and addressing. Formats: C4 and C8 with an RGB565/RGB5A3 palette, RGB565, RGB5A3, CMPR (the stage dictionaries use all of them); one mip level, same U and V addressing; sizes need not be a multiple of the tile (the padding is skipped).
- **`GXColor.h`**: RGB565 and RGB5A3 to RGBA8, shared by `Gvm` and `Txd`.
- **`GXTexture`**: `decodeCMPR` / `decodeRGB5A3` / `decodeRGB565` / `decodeC4` / `decodeC8` (one level of GX tile data to RGBA8, cropping the padding) and
  `gxDataSize`, shared by `Gvm` (CMPR, RGB5A3) and `Txd`. The C8 tile layout (8x4) is external and not checked by an image.
- **`RwMaterial`**: `readMaterialList` (color and base texture name of each material), shared by `Dff` and `World`.
- **`World`**: `Renderware::readWorld(bytes)` reads a Shadow stage's `.RG1` (name chunk + RenderWare World) into a `RenderWareWorld`: one sector
  (box + submeshes) per BSP leaf with geometry. Only GameCube native sectors are supported: the sector's BinMesh gives the material of each
  mesh and the native data holds GX vertex arrays (position f32x3, color RGBA8, UV0 f32x2, optionally UV1) and one display list of triangle strips per mesh,
  with 8 or 16 bit indices per attribute. Layout decoded from the disc and validated on all 3092 sectors of the 871 stage archives (no
  outside source for the native layout); the collision `.BSP` worlds hold plain data and are not read. Hypotheses (marked in the file): vertex color =
  color 0 x material color, strip winding, UV1 (probably a lightmap) ignored.
- **`Dff`**: `readDff(bytes)` reads frames (with HAnim node id), non-native geometry (positions, normals, first UV set,
  one morph target), the material list (prelit colors times the material color as vertex color (hypothesis: they tint gray textures; almost black ones, all of r, g, b below 32, are ignored as meant for the game's lights, which this engine lacks, e.g. Doom's Eye's body), base texture name) and atomics, into a
  `RenderWareMesh` with one submesh per used material, and the Skin plugin (per-vertex bone indices/weights, inverse bind
  matrices; skin bone i is HAnim hierarchy node i, mapped to the frame with that node id). Skipped: BinMesh,
  MatFX (environment map, UV transform), UV animation, material filter/addressing.
- **`STH2005::ONE` / `Prs`**: `.ONE` archive ("One Ver 0.60") with PRS-compressed entries, `readFile(name)`; also the
  pooled resource described above.
- **`.CCL`** (Shadow object collision, 1289 entries in the `One Ver 0.60` archives; `STH2005::readCCL` in `CCL.cpp`; `tools/dumpCCL.py`'s `parse_ccl` accepts all 1289 with the same rules and carries the full layout). External, from the Ghidra decompile of the retail `main.dol` (`shadowDecomp/`, untracked; the game's loader `FUN_8040e61c`/`FUN_8040e818`): big-endian, header of 0x20 bytes (size, A = size of section 1, B = size of section 2, 1, 0, `0x3142` whose byte 0x17 `'B'` the game reads as big-endian, 0, 0), section 1 = N records of 16 bytes `{type, pointer (offset from section 1), flags, id}` + a zeroed 16 byte struct + the data blocks, section 2 = the relocation stream of the pointers (N bytes, `'A'` then `'D'` x (N-1), zero padded), section 3 = `{0, 0}` (a group and its name), then the group's name. A record's type is the game's `Range` kind (Sphere 0, Box 1, Capsule 2, Cylinder 3, Plane 4, a Box subclass); the game's constructors copy 4, 10, 9, 9 and 10 floats. Block: Sphere = center, radius; Box/Plane = center, 3 half sizes, 3 angles, 0; Capsule/Cylinder = center, f3, f4, 3 angles, 0 (bounding radius f3 + f4 for a capsule, sqrt(f3^2 + f4^2) for a cylinder; scaling scales f4 with x and f3 with z). Hypotheses: angles in radians (axis order unknown, the game picks it per shape); f4 is the radius and f3 half the length along the shape's z axis. `readCCL` returns `Physics::CollisionShape`s: Sphere form 0, Box and Plane form 3, Capsule form 6 and Cylinder form 11 (a = radius, b = half length, both along the shape's z axis, hypothesis; 11 is this importer's own form so the SADX cylinders, forms 1 and 2, keep standing along y; the lines view draws both, the capsule with caps). Flags go to `attr`; the id, kind/push/damage are dropped/0; their meaning is unknown. Shapes stay in the file's own space (no `RenderWareYawDegrees`). Shadow himself has no `.CCL`: none in `character/*.one`, none named after him (only `SHADOWROBO.CCL`, the android), and `main.dol` names `.CCL` files only for two stage objects (`CN0000ROLLOBJECTNML`, `JG0000FVINEBALL`); observed in a RAM dump of the running game (user's), his body collision is one Capsule of radius 5.5 and zero length (f3 = 0, f4 = 5.5, no rotation) owned by a `CharaColliBody`; where those numbers are stored is not found (see `docs/UNKNOWNS.md`). The same dump also supports f4 = radius and f3 = half length: other capsules there are thin and long (f3 = 40, f4 = 4) and a cylinder is a flat disc (f3 = 0.75, f4 = 22, rotated 90 degrees about x).
- **`Placement`**: `STH2005::readPlacements(bytes)` reads a stage placement file (`sky2`, little-endian: 12 byte header, 44 byte records of position, rotation in degrees, two flag words, type id, sub type, parameter size, then the parameter block). Layout decoded from the four stg0100 files (sizes add up exactly). The type ids are the registry in `main.dol` at 0x8052b080 (external: 286 descriptors, name + id); which model/collision/animation an id loads is not read yet (the stage's `*_gdt.one` holds a `.BIN` recipe per object, undecoded). Only `DebugSetup::addShadowPlacementMarkers` uses it for now: crosses in the collision view (C key), colored by type, with `RenderWareYawDegrees` applied (hypothesis).
- **`RingLine`**: `STH2005::readRingPositions(placement)` gives the positions of the rings one RING record (type 16) stands for: its 20 parameter bytes are `u32 shape, u32 count, f32 a, f32 b, u32`; shape 0 puts every ring at the position, shape 1 (the only one in stg0100) a line of `count` rings, ring i at `(0, 0, -a / count * i)` in the record's frame (rotated about Y then X; the Z rotation does not move a point on that axis). External, from the decompile of the ring object (`FUN_80112cbc`); angles in degrees and the axis order are hypotheses. Shapes 2 and 3 (circle, wave) are not read and throw. `EntityKey::layout` (`PlacementLayout::RingLine`, set by the generator for the `RING` BIN) makes `Level::setONEEntities` create one entity per ring.
- **`Bon`**: `.BON` skeleton: bone id (matches the DFF HAnim id), name, parent, rest translation/rotation/scale.
- **`STH2005::Model`**: `STH2005::importModel(name, archive, parts)` (adds the mesh to `archive.meshes`, returns its index). `parts[0]` (DFF + BON) is the main model (without a BON it is a static model, e.g. stage objects, and the only part); frames take
  their names from the BON. Each later part with a BON replaces the main model's bone of the same name as its root bone;
  a part without a BON attaches its atomic's frame to the main model bone named in `STH2005::ModelPart::bone`.
  Hypothesis (marked in the file): the game places parts this way. Skin bone frames are remapped with the part's frames.
- **`STH2005::Mtp`**: (a key's marker bit 0 is bit 8 of its frame: observed on DOOMSEYE.MTP, frames 0, 199, 398, 480) `readMtnMotion(bytes, name, bon)` decodes a `.MTN`, one motion in a `.MTP` motion's layout (observed on SPRING00_ANM.MTN: same header, skeleton name and tracks; its size word equals the file size); `MotionKey::mtp` ending in `.MTN` selects it (`ONE::useMotion`). `readMtp(bytes)` lists a `.MTP`'s motions (name, offset, size, an unknown field); `readMtpMotion(bytes,
  name, bon)` decodes one into an `STH2005::Motion`: per bone of the `.BON` its translation, rotation and scale tracks (keys:
  frame, in tangent, tangent, value as half floats; the in tangent equals the tangent except on `sh_slow_skate`'s rotation
  keys with two tangents, whose order is a hypothesis). Layout observed on `SHADOW.MTP`: all 158 motions fit (9 tracks for
  the first node, 12 for the others, three of those unknown and ignored; a track's size is 9 bits).

## Conventions seen in the code
- `struct` everywhere, public members, `this->` on member access.
- Function parameters end in `_` (`position_`, `pId_`); references are prefixed `r`
  (`rCamera_`, `rInstance`).
- Types and namespaces PascalCase; functions and variables camelCase.
- Origin is carried by namespaces, not name prefixes: `STH2005::ONE`, `Ninja::importGvm`, `GameCube::openGCDisc`,
  `Renderware::readDff` (file names keep the origin only where the folder is flat, e.g. `STH2005Keys.h`, `STH2005Motion.h`).
- `#pragma once`; small utilities as header-only `inline` functions.
- Explicit lifetime methods (`init`/`create`/`destroy`) instead of RAII.
- OpenGL 4.5 direct state access (`glCreateBuffers`, `glNamedBufferStorage`, `glBindTextureUnit`,
  `glVertexArray*`), except `Texture::create`, which uses bind-to-edit.
- Errors: `throw std::runtime_error`, with `std::format` messages.
- Comments: one `/* ... */` block before each logical block with non-obvious behavior; evidence labeled as decoded
  from a file, external, or hypothesis.
- Indentation mixes tabs and 4 spaces; braces are mostly on their own line.

## Incomplete or inconsistent (as of this snapshot)
- No lighting. Alpha blending is on (`GL_SRC_ALPHA`, `GL_ONE_MINUS_SRC_ALPHA`, unsorted, texels with alpha < 0.01 are discarded in the `SA` and `STH2005` shaders), but only a texture's own alpha and the vertex color alpha count: an SA material's alpha and its alpha attribute bit are not read, so water and glass stay opaque unless their texture has alpha. The bits of an SA material's attributes that are read are the UV clamp ones (see `SAMdl.cpp`); the flip bits are unknown. Material diffuse colors of SA models are ignored; vertex colors are white. Animation is limited to the idle motions wired in `main.cpp`: SADX at 30 frames/s and Shadow at 60 are hypotheses, and the Euler rotation order of Shadow's motions is unverified (see `ONEInstance.cpp`).
- Shadow's MatFX environment maps and UV transforms are not implemented (the environment textures `pl_bl01n`,
  `pl_hnshd0` are loaded but unused); `.UVA` files and the weapon hands/effects are not imported. Only the idle motions are wired (`sh_idle`, `lte_idle`, `rte_idle`); the other hand models (gun, bar, sword) and their motions are not.
- A level's pieces are bound once per texture set (`TextureSet::saBindings`), so two land tables of one set sharing a model would share the first's texlist order. Level start positions and objects (SET files) are not read; the camera starts at a placeholder.
- SADX welds (vertices shared between limbs) are not imported, so gaps can show at Sonic's joints while he animates.
- Textures filter/wrap: `Txd` applies the TXD's value (nearest) while the DFF materials say linear; unresolved.
- Shadow levels: no collision (`.BSP` is not read), no fog (`.fog`), lighting or lightmaps (UV1, `_light.bin`), no objects (`_gdt`, `_dat`) and no stage start
  positions (the camera starts at a placeholder); what the `.RG1` kinds (`O`, `OS`, `OW`, `A`, `AF`, `K`, `G`, `D` in the entry names) mean is unknown, all are drawn. A level
  loads every section archive of the stage at once. Strip winding and the 90 degree yaw for worlds are unverified.
- `initGlad` in `Utils.h` is unused; `Renderer::init` loads GLAD itself without registering the debug callback.
- `BoneAnimation.h` is empty; SA instances (an SAMotion) and ONE instances (an STH2005::Motion) set a pose.
- `DebugUI` uses ImGui with the GLFW and OpenGL3 backends (`#version 450 core`, the framebuffer's sRGB is switched off while it draws, no `imgui.ini`): one "Debug" window with tabs (Camera, Physics, Collision, Markers). The cursor is captured by the camera until Tab frees it (`Globals::Mouse::cursorFree`: visible, `mouseCallback` ignores it); a left click anywhere the UI does not cover (`DebugUI::wantsMouse`) captures it again, with the next position as the baseline. The Collision tab has the switches of the lines view, a draw distance slider and a clickable legend of the values. nlohmann/json is not referenced by CMake.
- `PoolMap::getIdByName` only checks for a missing name in Debug builds.
- `STH2005::ONE` owns GPU data (its meshes and textures) and includes `GPU_Globals.h`.
- Shadow resources are counted per archive only: meshes, `.TXD`s and `switchMeshPart` variants stay until the archive is freed.
